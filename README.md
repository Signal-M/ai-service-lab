# Service Lab · 私域 AI 客服项目复刻

一个**真正跑通完整业务流**的私域 AI 客服后台复刻项目：从用户一句话开始，走完 **意图识别 → Prompt 组装 → LLM 意图理解与规划 → RAG 检索 → 知识生成 → Tool 调用 → Trace 全链路回放**。

## 这不是一个静态页面

需要特别说明：**它不是 UI 稿、不是静态 Demo 页面，也不是只有一个聊天框的前端壳子。**

它是一个完整走通 **意图识别 / RAG / Tool / Trace** 四大模块的真实业务项目：

- **挂上大模型 API 就能真实对话** —— 不是写死的假回复，回复内容由知识库检索结果 + LLM 生成；
- **每一轮对话都真实执行完整链路** —— 意图识别、检索、生成、工具调用都是运行时真实发生的，可以逐节点看到耗时和 token；
- **有状态、有数据** —— 对话会沉淀成工单，工单关联 Trace，Trace 可回放、可重放、可加入 Eval。

## 界面一览

### 1. 对话模拟 & 执行轨迹

左侧是企微客服演练台，右侧是同一轮对话的执行轨迹。可以对着一条消息直接看到它命中了哪个意图、走了哪些节点。

![对话模拟与执行轨迹](docs/screenshots/01-chat-simulator-and-trace.png)

### 2. 工单列表

模拟对话产生的工单自动沉淀，每张工单对应一段对话，可以进入它的 Trace 查看完整执行过程。列表里能直接看到**主诉求分类**（`material_request` / `business_qa` / `course_consultation` / `refund_policy` / `human_request` …）和状态。

![工单列表](docs/screenshots/02-ticket-inbox.png)

### 3. RAG 知识库

chunk 级的知识库管理：支持按来源、Chunk ID、内容关键词过滤，可以浏览每个 chunk 的原文和元数据。知识来源是可追溯到具体文档章节的（如 `handbook.md` 第 5 章 / 第 10 章 / 第 12 章）。

![RAG 知识库](docs/screenshots/03-rag-knowledge-catalog.png)

### 4. Trace 运行图

一次任务的完整运行图：本轮的用户信息、工单主诉求、Agent 调用次数、外部动作次数、Token 消耗、总耗时，以及**逐节点的事件时序**（Code 节点 / LLM 节点 / Tool 节点），右侧 EVENT INSPECTOR 可以看到每个节点的真实输入输出。

![Trace 运行图](docs/screenshots/04-trace-runtime-map.png)

## 一轮对话的业务流

以截图里的一条真实链路为例，用户输入「语文」之后实际发生的事：

| # | 节点 | 类型 | 做了什么 |
|---|------|------|----------|
| 1 | Prompt 组装 | CODE | 已组装本轮完整 Prompt |
| 2 | 意图理解与规划 | LLM | 判断用户在问业务问题、是否要直连链路/先澄清 |
| 3 | RAG 检索 | TOOL | 多条 query、多路召回、命中可追溯，输出 `status: hit` |
| 4 | Prompt 组装 | CODE | 把 RAG 召回内容拼进上下文 |
| 5 | 基于知识征集生成回复 | LLM | 依据检索结果生成回答 |
| 6 | transfer_to_human | TOOL | 检索不足时转人工 |
| 7 | 发送最终回复 | CODE | 把结果返回给用户 |

**关键点**：检索不足时系统会明确告知「暂时没在业务资料里找到可靠依据，已经登记并帮你转人工确认」，而不是编一个答案——这是这个项目在设计上最在意的地方。
